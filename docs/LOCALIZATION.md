# 语言切换与多语言文档

[文档中心](README.md)

## 前端语言规则

控制台、登录、独立搜索和资产详情共享中英文语言选择器。首次访问读取浏览器的首选语言：`zh` 及其地区/书写变体使用简体中文，`en` 及其变体使用英文，其他语言、空值或不支持的语言使用英文。不会因为第二偏好为中文而覆盖第一偏好。

手动选择后，浏览器 cookie `network_mapping_locale` 保存 `zh-CN` 或 `en`；下次访问 cookie 优先于浏览器语言。cookie 有效期一年、`Path=/`、`SameSite=Lax`，HTTPS 下设置 `Secure`，不设置 Domain；仅用于展示，不参与鉴权。首次自动选择不写 cookie。无效、损坏或不支持的 cookie 被忽略。浏览器禁止 cookie 时当页仍可切换，并提示保存失败。

选择立即生效，不重新加载业务页，不清空未发送输入、筛选或未保存表单。跨页面沿用 cookie，其他已打开页面在重新获得焦点或可见时同步；浏览器支持 Cookie Store 事件时也会即时同步。清除 cookie 后重新按浏览器首选语言选择。

语言不改变系统业务时区、日期格式、小时制、绝对时间、扫描目标、协议枚举或权限。采集证据、产品名、用户输入、LLM 对话和已保存的通知模板保持原文。服务端返回的自由文本、历史诊断与未提供稳定错误码的详细错误可能仍保留原语言；不将这些内容发送给在线翻译服务。

## 文档站语言

文档站中文保留原路径，英文位于相同站点基址下的 `en/`。右上角语言菜单链接到对应页面；尚无同页英文时进入英文首页，明确链接中文原文。文档首页按浏览器/cookie 选择语言，手动文档菜单选择也写入相同 cookie。语言菜单链接携带白名单参数 `docs-lang=en` 或 `docs-lang=zh-CN`，在目标首页优先于 cookie 和浏览器偏好；即使 cookie 被禁用或静默拒绝，也能切换、刷新、复制链接或在新标签页打开所选语言。未携带该参数的新首页访问仍按 cookie/浏览器偏好选择。普通中文专题不强制跳转，便于阅读尚未翻译的内容。

本仓库英文首批包含首页、部署入门和语言维护三页；其他专题保留中文。菜单、搜索分词、编辑路径和生成页面分别按语言配置，不能将中文搜索支持英文词视为已有英文内容。

## 安装、预览与构建

从 `network-mapping-vue` 仓库根目录执行，要求 Python 3.10+：

```sh
python3 -m venv .venv-docs
. .venv-docs/bin/activate
python -m pip install -r mkdocs/requirements.txt
python scripts/build-docs.py
```

统一命令对中英两套配置严格构建，先生成中文，再生成 `mkdocs/site/en/`，整体产物位于 `mkdocs/site/`。单独构建中文会清理输出，因此发布两种语言必须使用统一命令。静态站点应托管整个输出目录。只构建，不自动发布。

```sh
# 预览完整中英产物，打开 http://127.0.0.1:8000
python -m http.server 8000 --bind 127.0.0.1 --directory mkdocs/site
# 只编辑中文时可使用 MkDocs 自动刷新
python -m mkdocs serve -f mkdocs/mkdocs.yml
```

`mkdocs/mkdocs.yml` 与 `mkdocs/mkdocs.en.yml` 的 `site_url` 是站点 canonical 基址，发布前改成此仓库实际托管地址，并确保三个组件不会覆盖同一部署目录。默认值沿用原站点示例，不表示已发布到该域名。语言菜单采用相对链接，支持子路径和本地静态预览。

## 添加译文与检查

1. 中文专题保留原路径；英文以相同相对路径放到 `docs/en/`，保持命令、配置键、协议标识和版本边界不变。
2. 英文首页维护已译清单及中文原文入口；新增译文同步英文导航。当前未启用自动翻译或缺译页复制。
3. 每次行为变化同步中文、相关英文及 `CHANGELOG.md`。部署、恢复和权限步骤由维护者审核，未核对的译文不加入发布导航。
4. 运行统一严格构建和 `python -m unittest discover -s mkdocs -p 'test_*.py'`。语言脚本回归另运行 `node --test mkdocs/language.test.cjs`（Node.js 20.19+，无额外 npm 依赖）。检查语言链接、搜索、根 README/源码跳转、子路径、编辑链接及页面锚点。

钩子从自身位置确定仓库根，英文的 `docs_dir=docs/en` 不会把 `docs/` 误当作仓库根。站内同语言链接使用相对 Markdown 路径；源码及站点根以外的现存仓库文件转为 GitHub 链接，保留 query/hash。越出仓库或不存在的文件不自动改写，交由严格构建暴露问题。

## 前端词库维护

`src/i18n/locale.js` 负责纯语言选择和 cookie 规则；`src/i18n/index.js` 提供共享 Vue I18n 实例、响应式 locale、`tr()` 和手动切换。`src/i18n/en.json` 以保留在源码中的中文展示文案为索引；内部映射到不含标点的消息键。消息函数保留例子中的 `@`、`|` 和花括号，参数仅做文本插值，不解释 HTML。

新增界面文案时在组件或显示工具调用 `tr('中文文案')`，并添加对应英文。动态文案使用 `{0}`、`{1}` 等槽位，参数原样保留。静态选项字典的 label 使用 getter，图表在响应式上下文读取 locale，避免仅初始化时翻译一次。已有缓存提示可在展示时使用 `uiText()`；不得对文章、证据、用户名称、模板正文等数据调用该辅助函数。

UI 时间显示通过 `src/i18n/time.js` 使用当前语言；日期计算和既有导出的默认 formatter 继续位于 `utils/systemTime.js`。图表可显示翻译后的系列名，`rawName` 为兼容导出保留原列名。统计明细 CSV 也使用独立的固定列名、状态、布尔值与时间 formatter；Top N 合并行使用 `synthetic` 标记禁止下钻，不比较翻译后的标签。修改界面时同时检查 CSV、协议值和请求体，不按翻译文案判断业务状态。

Statistics 的类型名称按稳定类型 ID 映射到界面词库；默认图表标题随语言更新，自定义标题保持用户输入。统计口径、对比和明细说明仅对已有词条进行本地翻译，未知说明保留原文。图片导出使用当前界面语言；CSV 保留原有字段和值，Top N 合并行也固定使用中文“其他”。不要把翻译后的类型名称写回接口目录数据。

```sh
pnpm test:i18n
node --test src/utils/*.test.js src/components/*.test.js src/views/*.test.js
pnpm build
```

词库检查会拒绝空译文、缺失词条或不一致的插值参数。既有中文业务测试显式选择中文，新测试独立覆盖英文、cookie、响应式标签、时间展示与 CSV 兼容。MkDocs 两种语言和链接钩子另有独立 CI。
