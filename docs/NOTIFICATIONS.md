# 通知渠道管理

[返回文档中心](README.md)

进入「设置 → 通知渠道」（`/setting/notifications`）。邮件、飞书、Telegram 在同一页面以同级渠道展示，可任选一种或同时启用多种；各自选择事件，不互为主备。

## 配置与订阅

点击「添加通知渠道」，选择类型并填写配置：

| 类型 | 配置 | 凭据编辑 |
| --- | --- | --- |
| 邮件 | SMTPS 服务器、端口、发件邮箱、授权密钥、可选收件人 | 密钥留空保留 |
| 飞书 | 群机器人 Webhook、可选签名密钥 | Webhook/密钥留空保留，清除签名须勾选 |
| Telegram | Bot Token、Chat ID 或公开频道 @名称 | Token 留空保留 |

三个渠道均可选择健康告警、Scanner 掉线、Scanner 恢复、用户登录、周报生成、月报生成。选择「仅严重」只发送严重健康告警；其余事件为 warning。渠道类型创建后不能改，请新建对应类型。

邮件收件人可每行一个或用逗号分隔，最多 32 个。留空时登录通知发给用户本人，报告使用计划所选管理员，其余为当前启用的管理员。旧 SMTP 配置只导入一次，旧测试收件人不会变成真实收件人。

飞书关键词校验须允许 **Network Mapping**。Telegram 机器人须先加入目标群/频道并可发送消息，私聊须先发送 `/start`。服务端出口分别允许 `open.feishu.cn:443`、`api.telegram.org:443` 和 SMTP 服务器；Web 不需要公开机器人回调。

## 操作与状态

- 各渠道独立启停；可同时启用多个渠道接收同一事件。停用一个不会改变其他渠道。
- 「测试发送」须先保存并启用，同渠道至少间隔 30 秒。已入队不代表送达，以投递结果和实际收到消息为准。
- 修改/停用/删除取消旧配置下未完成的任务；已发请求不能撤回。再次启用只接收新事件。
- 投递历史支持渠道/状态筛选和游标翻页；浏览旧历史时暂停自动刷新。
- 离开页面取消读取请求并停止轮询，迟到响应不更新已卸载页面。
- failed 可手动重试，至少一次投递可能重复；查看事件 ID 排查。过期、取消、目标已变更的任务不会直接恢复。
- 维护期间每次领取前检查状态，允许在途完成；退出后处理待投递记录。
- 版本冲突 409 时刷新后重试。服务端和页面都只允许管理员管理。

报告生成时间、计划和默认邮件收件管理员在报告中心管理，通知方式在本页面管理；无需邮箱也能使用飞书或 Telegram 接收报告通知。报告中心显式发送/重发完整邮件、邮件模板测试继续使用首个邮件渠道的 SMTP 配置。

## 分渠道模板与预览

入口为「设置 → 通知模板」(`/setting/notification-templates`)，旧地址 `/setting/mail-templates` 保留。邮件沿用 HTML 和备用纯文本编辑器；飞书与 Telegram 按事件独立选择纯文本或富文本，支持自动预览、草稿、发布及历史恢复。同类渠道共用其事件模板。

飞书支持粗体、斜体、下划线、删除线、链接，后端转换为原生 `post`；Telegram 使用 HTML parse_mode，另支持 code、pre、blockquote 和 tg-spoiler。本编辑器不支持 CSS、图片、任意网页 HTML 或卡片 JSON。变量自动转义，事件 ID 自动附加。

三个渠道均有在线预览。飞书与 Telegram 是浏览器模拟预览，未接入官方客户端原样预览；字体、主题、剧透、链接提示可能不同。效果、纯文本和最终消息数据可切换查看。预览不发消息、不加载外部资源；渠道页测试仍发送固定连通性消息；模板编辑器内测试发送当前内容。真实数据超长时投递记录会显示模板渲染错误。

后端须同步升级，新增 API 位于 `/api/notifications/templates/{provider}/{event}`，提供 GET 详情和 POST preview/draft/publish/restore。写入使用 revision 防止覆盖其他管理员的修改。保存冲突保留本地编辑，重新加载前请备份需要保留的文本。邮件 API 不变，旧模板和已归档报告不变。

详细格式、变量、消息长度和迁移约定见服务端文档：[分渠道通知模板](https://github.com/wshijiang/network-mapping/blob/main/docs/NOTIFICATION_TEMPLATES.md)。


### 与邮件一致的变量和模板测试

邮件、飞书、Telegram 共用代码编辑器的样式、变量自动补全和点击插入方式。机器人参数目录按事件复用邮件的字段名称、说明、示例和结构，包含登录 source_ip、健康 details、Scanner 详情和周报/月报嵌套统计。真实投递使用共享事件数据；报告使用归档参数快照。新默认富文本参考邮件的标题、详情、建议和操作入口，已保存版本不会被覆盖，可载入默认模板后自行发布。平台不支持的 CSS、图片和布局不会强行移植。

在飞书、Telegram 模板中选择已启用的同类型渠道及示例级别，点击「发送测试消息」，即可发送当前编辑的内容，无需保存或发布。页面展示投递 ID，并跟踪排队/发送/成功/失败状态；超出约 60 秒可到通知渠道查看投递记录。测试只发送固定示例数据；同渠道每 30 秒一次，与连通性测试共用限流。

接口：`POST /api/notifications/templates/{provider}/{event}/test` 接收 `{channelId,source,severity}`；`GET /api/notifications/deliveries/{id}` 查询结果。预览接口增加 `?severity=warning|critical`。测试快照进入既有队列，后续编辑不会改变已排队内容，离开页面会停止状态轮询。

## 渠道代理

创建与编辑渠道均提供“沿用系统 / 直接连接 / 指定代理”。适用于邮件、飞书、Telegram；指定地址支持 HTTP、HTTPS、SOCKS5、SOCKS5H，后者在代理端解析目标域名。代理地址作为密码输入，认证信息保存后不回显；编辑留空保留，改为沿用系统或直连后保存会清除已存代理。沿用系统保持旧行为：HTTP 使用环境代理，SMTP 直连。

列表仅展示移除认证信息的地址摘要。选择自定义代理后连接失败不会回退直连；SMTP 与代理的 TLS 证书分别验证。测试发送前先保存渠道，模板测试和手工报告也沿用首个邮件渠道的代理。需先部署支持 proxy_mode/proxy_url 的后端；旧后端会拒绝新增字段。

代理状态变化仍有配置版本校验；仅改代理保留原收件目标版本和掉线/恢复通知关联。测试覆盖地址校验、留空保留、模式切换、认证信息不回填与错误脱敏。
